## The problem

If you work with coding agents every day, three questions keep coming back.
How close am I to my plan's limit, and when does it reset?
What is this costing, and who pays for which part?
Where does the usage go: which projects, sessions, subagents, skills and MCP servers?
The agents answer only part of that, one machine and a few days at a time, and Claude Code deletes its transcripts after 30 days by default.

## What I built

A dashboard for the agents I use myself, made to sit where the work happens.

- **Plan limits at a glance.** Claude Code's five-hour and weekly windows and Copilot's monthly allowance, with when each resets and, at the current pace, where it will end.
- **Cost that says where it comes from.** Every figure is labelled as recorded, estimated or mixed. An unpriced request shows as unpriced, never as $0.
- **Each agent apart.** Agents are often paid for by different people, so usage is split by agent before anything is added up.
- **Where it goes.** Projects, sessions, subagents, skills, MCP servers, models and how well the prompt cache works.
- **History that lasts.** It keeps what it has read, long after the agents' own transcripts are gone.
- **Local and private.** No telemetry, no prompt or code content stored, and the network used only for features you switch on.

## How it is built

One Rust core reads the agents' own files into a single history, and three surfaces sit on top of it:

- a **VS Code extension** with a status bar item, a sidebar summary and the full dashboard in a panel or an editor tab, working over WSL and SSH;
- a **desktop app** built with Tauri, with a tray item, signed automatic updates and installers that need no administrator rights;
- a **terminal UI** that works from the keyboard alone, plus reports with `--json` and `--csv` output for scripts.

The VS Code and desktop surfaces share one React interface, drawn in each host's own theme, high contrast included.
Seventeen architecture decision records explain the choices.
About 410 Rust tests cover the core, and Playwright tests check every section for visual changes and accessibility in each theme.
Releases ship for Windows, macOS and Linux on x64 and arm64.

## Where it stands

agent-dashboard is at version 2.1, released on 12 November 2026.
It is open source and installed from its GitHub releases.

## What this means for you

It shows how I build software for real use: start from the questions people ask most often, be honest about where every number comes from, and test what people see, not just the code behind it.
