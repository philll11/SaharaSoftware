## The problem

A large European construction company runs hundreds of business processes on Boomi, looked after by a small team of integration developers.
Boomi's test mode is manual, and its logs are gone once you leave it.
Boomi Assure is not built for a team's own regression testing.
That left the team without a shared record of which tests prove which component, what last ran, on which revision, and who started it.
Before changing an integration, a developer had no quick way to see what would prove the change worked.

## What I built

An automated regression testing platform, with a web app and a command line.

- It reads the Boomi account into its own catalogue.
- It records which test proves which component, so coverage is visible before a change, not after.
- It runs tests on the customer's own runtimes, on demand or on a schedule.
- It keeps every result against the exact revision tested, so "it passed" always says what passed.
- Roles and an audit trail show who did what.

Running tests is not the hard part; a home-built harness can do that.
The record around the tests is what a team was missing, and that is what Testify keeps.

## How it was built

I made the design decisions and an LLM wrote much of the code, over weeks of development work rather than months or years.
The controls around that code are what make it fit for production:

- every pull request runs automated checks that block the merge, across about 5,700 test cases in the code;
- every commit is scanned for credentials before it is made, so a secret never reaches the server;
- a person approves each release to production, and production receives the exact image that ran in test.

Azure hosting for the test and production environments comes to an estimated EUR 230 a month.

## Where it stands

Testify is live in production at the client, used by its integration team.

## What this means for you

If you run on Boomi, I can bring this platform to your account.
If you do not, the lesson still applies: for any integration your business depends on, you should be able to see what was tested, when, and against which version.

The client and its data stay private, so this page shows the design rather than screenshots.
